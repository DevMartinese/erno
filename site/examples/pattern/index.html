Pattern

Write a function of a cubie's position and the engine paints a puzzle with it. Then scramble it and bring the pattern back, by hand or by writing the sequence. Two puzzles stacked: one you write, one you turn.

This page is not part of the library. It is one file of glue over the public API, kept here to show what the engine is for.

Write

Your function runs once per cubie, with x, y and z at its place on the lattice and n at how far that lattice reaches. Return a colour.

A cube already names six of them, and not red and blue: U, R, F, D, L, B, the same alphabet its moves are written in. So return y > 0 ? U : D reads like a cube. Numbers 0 to 7 reach a wider palette for the pictures six face colours cannot make.

Nothing here is a special mode. paint is an ordinary option on an ordinary cube, so what comes out is a working puzzle and not a picture of one.

Solve

The goal is the cube you just wrote, at rest. That matters more than it sounds: the target is reachable because the puzzle was standing on it a moment ago, so no solver is needed and no impossible pattern can be asked for.

The move buttons ask the puzzle what is available rather than assuming. On a plain cube everything always is. Point the same code at a welded or bandaged puzzle and it stops being true, which is why the question is asked at all.

The buttons turn one face; the box below turns a sentence, in the notation cubers already write. [R, U] is a commutator, [R: U] a conjugate, (R U)3 a repeat. What it prints back is not the move list but what the sequence does: which pieces travel together, how many are touched, and how many repeats bring it home. A commutator moving three pieces and nothing else is the whole reason they are taught, and it is one line here rather than a lecture.

The code

        

          Not an example written once and left to rot beside the thing it
          describes. This is generated from the same state the page is
          drawing from, so it cannot drift: change the puzzle and the
          constructor changes, weld two bodies and the bodies appear, turn a
          face and the move shows up, type a sequence and its permutation is
          printed under it.
        

        

          It is meant to run. Put it in a file beside the library and you get
          the puzzle above, in the position above. There is a test that
          pastes it into node and checks that it does.
