erno.js A tiny engine for twisty puzzles rendered to SVG

erno.js is a minimalist JavaScript engine that holds the state of a twisty puzzle — an N×N Rubik's cube, a Skewb, a Pyraminx, a Mirror, a Void, a Rubik's Tetris, a cuboid, a shape mod or a corner/edge turner — applies moves in standard WCA notation, and distills every position into pristine SVG. No WebGL, no canvas: the output is semantic, stylable, resolution-independent markup, with data attributes on every sticker.

The cube core tracks facelets the way solvers do — the state string is solver-ready — while the classic variants run on a generic piece engine: each puzzle is described as a solid plus cut planes, and every piece carries an exact integer rotation, so a scramble and its inverse restore the solved state bit for bit.

erno is the sibling of heerich.js (voxels → SVG) and shares its philosophy and its render pipeline lineage. It is named after Ernő Rubik, who in 1974 glued the first prototype together out of wood and paper clips.

This page is both manual and playground. Every example below is live — use the settings panel to swap cameras and sticker styles across the whole page.

Creating a cube

An Erno instance holds the facelet state of an N×N×N cube and knows how to project it into 2D SVG. You initialize one with a size, a tile size in pixels, and an optional camera. 

import { Erno } from 'erno'

const cube = new Erno({
  size: 3,
  tile: 40,
  camera: { type: 'isometric', angle: 30 },
})

cube.move("R U R' U'")
document.body.innerHTML = cube.toSVG()

All parameters are optional — new Erno() is a 3×3 with sensible defaults. The SVG auto-centers on the visible geometry; pass { fitSphere: true } to size the viewBox to the cube's circumsphere instead, so animations never make it jump.

Moves & notation

move() accepts standard WCA notation, whitespace-separated: face turns R L U D F B with ' and 2 suffixes, wide turns (Rw, lowercase r, or 3Rw on big cubes), slices M E S, and whole-cube rotations x y z. 

cube.move("R U R' U'")  // chainable
cube.move("Rw M2 x'")
Erno.inverse("R U2 f'") // → "f U2 R'"

Internally every move is a permutation of facelet indices, derived once from exact integer 3D rotations and cached — applying a move is a single array shuffle.

Scrambling

scramble() applies a random move sequence — avoiding trivially redundant successors — and returns it, so you can show it, store it, or invert it. 

const seq = cube.scramble()
cube.move(Erno.inverse(seq))
cube.isSolved() // true — exactly

Facelet state

State is a facelet string in URFDLB face order, row-major per face, one letter per sticker naming its home face — the same layout common solvers (e.g. Kociemba's) consume, so wiring a solver up is a string away. 

cube.getState()
// "UUUUUUUUURRRR…"
cube.setState(str)

Cubes of any size

The same engine renders a 2×2 pocket cube, the 3×3, and any big cube — wide turns like 3Rw included. Facelet count grows as 6N², and moves stay a single permutation. 

new Erno({ size: 2 })
new Erno({ size: 5 }).move("3Rw U 3Fw'")

Skewb

The corner-turning cube. Moves follow WCA Fixed Corner Notation: R U L B each turn half the puzzle 120° clockwise around a corner, ' for counterclockwise. Shift-click the buttons for primes. 

import { Skewb } from 'erno'

new Skewb().move("R U' L B").toSVG()

The classic variants all run on a generic piece engine: a solid plus cut planes, sliced into pieces, each carrying an exact integer rotation. Same API as the cube, plus data-piece on every polygon.

Pyraminx

The tetrahedron. Uppercase U L R B turn a vertex's two layers; lowercase u l r b turn just the trivial tips. Scrambles append random tip moves, WCA style. State is 36 facelets in FLRD face order. 

import { Pyraminx } from 'erno'

new Pyraminx().move("U L' R b")
new Pyraminx().scramble()
// "U L R' B u' r"

Mirror cube

A 3×3 with uneven cuts and uniform stickers — the blocks shape-shift as you scramble, exactly like the real puzzle. It speaks full cube notation, and because the pieces are tracked on a logical 3×3 grid, getState() still returns virtual URFDLB facelets identical to the plain cube: solvers work unchanged. 

import { Mirror } from 'erno'

const m = new Mirror()
m.move("R U2 F' D") // shape-shifts
m.getState()        // 3×3-compatible

Void cube

A 3×3 without centers. The piece engine renders interior plastic walls, so the holes go all the way through — turn the camera and you can see the background straight down the tunnels. 48 facelets, 8 per face; slices still turn the edge ring. 

import { Void } from 'erno'

new Void().move("M E' S2")

Rubik's Tetris

The official Rubik's × Tetris mashup: a 3×3 whose 26 cubies are solid-colored blocks. Solved, every face reveals one classic Tetrimino in its Tetris color around that face's center — all of them except the I, which doesn't fit a 3×3 face (the real product ships it as the display stand). Two cubies stay white, like the logo tile on the physical puzzle. 

import { Tetris } from 'erno'

const t = new Tetris()
t.scramble()
t.isSolved() // visual check: same-colored
             // cubies are interchangeable

Because the pieces are solid-colored, isSolved() compares the visible pattern, not piece identity — swapping two same-colored cubies still counts as solved, exactly like the real puzzle.

Cuboids

Non-cubic boxes, any nx×ny×nz. The engine enforces the physics: quarter turns are only legal about an axis whose cross section is square; everywhere else the shape only returns to itself after a half turn, so R throws and R2 works — the box never shape-shifts. The classics ship as presets: Domino (3×2×3, Ernő Rubik's 1978 puzzle before the cube), Tower (2×3×2) and Floppy (3×1×3, nothing but 180° flips). 

import { Cuboid, Domino,
         Tower, Floppy } from 'erno'

new Domino().move("U R2 D' F2")
new Floppy().move("R2 F2 L2")
new Cuboid({ size: [3, 4, 3] })

On the Domino, U and D spin freely while the sides flip — scrambles mix white and yellow on the same face, just like the real thing.

Shape mods

Cube and 2×2 groups wearing different bodies. The Fisher (Tony Fisher, 1985), Windmill, Axis and Ghost cubes are a 3×3 mechanism rotated inside the cube shell — the Ghost by a compound odd angle, in monochrome. The Twist is molded pre-twisted, the Penrose is sculpted into three smooth shells, and the morphix pair puts a 2×2 / 3×3 mechanism inside a tetrahedron. 

import { Fisher, Windmill,
         Twist, Penrose } from 'erno'

new Fisher().move("R U' F")
new Penrose().scramble()

Mid-shape-shift, stickers can face directions that belong to no face of the cube — those positions report ? in getState() until they realign.

Corner & edge turners

The Dino cube's cuts trace the face diagonals: twelve edge pieces and nothing else, turned three at a time 120° around a corner — moves are named by their corner (URF, DBL'…). The Helicopter turns 180° around its twelve edges (UF, FR…): eight corners and twenty-four single-sticker petals. 

import { Dino, Helicopter } from 'erno'

new Dino().move("URF UBL' DFR")
new Helicopter().move("UF FR DB")

The corner-name buttons drive the Dino, the edge-name buttons the Helicopter.

Beyond the cube

The engine carves pieces out of any convex solid, so the base shape is just another part of the definition. The Megaminx is a dodecahedron cut by twelve planes, one per face — sixty-two pieces, each face a centre pentagon ringed by five edges and five corners, every turn a fifth of a revolution. Cut deeper and the edges disappear, leaving the twenty corners of the Kilominx. The Skewb Diamond is the Skewb's dual: the very same four cuts and moves, applied to an octahedron. 

import { Megaminx, Kilominx, SkewbDiamond } from 'erno'

new Megaminx().move("A C' F")   // faces are lettered A–L
new SkewbDiamond().move("U R'")

A dodecahedron has no up or right, so its twelve faces are simply lettered A–L and each letter turns its own face. The Skewb Diamond keeps the Skewb's U R L B.

Color schemes

Face colors are just an option — SCHEMES ships the Western/WCA classic, the Japanese scheme, and uniform silver and gold. Western and Japanese share white top, green front and red right, so from the default view they look identical; the difference is on the hidden faces — Japanese puts blue opposite white (down) and yellow opposite green (back), where Western has yellow down and blue back. This demo starts rotated (x2) so the bottom and back are in view. 

import { SCHEMES } from 'erno'

new Erno({ colors: SCHEMES.japanese })
new Void({ colors: SCHEMES.gold })

Generative color

Beyond the presets, schemes can be generated: a hue walk around the wheel with eased saturation and lightness yields an endless supply of harmonious face colors, reproducible by seed. schemeFrom() derives a whole scheme from one color — hand it a brand hex and the cube dresses to match. A generated ramp painted across the pieces turns scrambling into a mosaic maker. 

import { generateScheme, schemeFrom,
         generateRamp } from 'erno'

new Erno({ colors:
  generateScheme("URFDLB".split(""),
    { seed: 42 }) })

schemeFrom('#e63946', [..."URFDLB"])

The ideas come from rampensau (hue cycling), poline (palettes as sampled paths) and dittoTones (palettes from one color) — the color-tool universe of heerich's author.

Functional styles

style() takes a static object merged into every sticker, or a callback ({ face, row, col, letter }) → style — the vocabulary of tutorial diagrams: gray out everything but the cross, highlight an F2L pair, dim solved layers. 

cube.style(({ face, row, col }) =>
  face === 'D' || row === 2
    ? null                  // keep color
    : { fill: '#d4d4d4' })  // dim the rest

Animating turns

toSVG({ turn: { move, progress } }) renders any position mid-turn — the layer rotates continuously and the plastic core is exposed. Drive progress from requestAnimationFrame and you have a player; pair it with fitSphere so the viewBox holds still. 

cube.toSVG({
  fitSphere: true,
  turn: { move: 'R', progress: 0.5 },
})

This demo plays the T-perm. It works on every puzzle.

Stateless rendering

Erno.renderState() renders a facelet string without keeping an instance — size inferred from the length. Feed it solver output or precomputed positions and render hundreds of algorithm diagrams at build time. 

Erno.renderState(
  'UBULURUFU…', // any 6N² facelet string
  { camera: { type: 'isometric', angle: 30 } }
)
